## 标注约定 v0.1

Schema 位于 `m0/score.schema.json`。当前只处理一个裁剪 system，单轨单声部；不宣称完整 Score/Track、技法、调弦或导出语义已经实现。输入采用 JSONL，一行一个样本；示例见 `data/examples/truth.jsonl`。

- 弦号 1 为最上方的高音弦；品位按原图整数记录。和音放在一个 event 的 notes 中，一弦只能有一个品位。
- 按阅读顺序记录小节与事件。IDs 在单一样本内唯一，仅用于编辑和定位，不参与识别计分。
- onset/duration 用四分音符为单位的 `{ "n": 1, "d": 2 }`；无法从图像确定则为 null，必须填写 unknownReason，不能补默认节奏。
- region 是裁剪图像像素坐标 `[x0,y0,x1,y1]`；暂无法定位允许 null，但需另记定位缺失，不能据此声称具备点击校对能力。
- rest=true 要求 notes 为空；普通音符必须有 notes。
- 无法纳入 v0.1 的连音组、技法或复杂声部先记入样本旁的人工问题清单，不进入精简评分集，不能悄悄丢弃后宣称整页完整识别。

## 真实数据收集与隔离

在忽略目录 `data/private/` 保存有权处理的截图和标注，不提交用户谱图。先收 5 张试标，修订标注规范后冻结，再扩充至 50 张。建议覆盖 GP、MuseScore、中文应用截图，以及清晰、压缩、裁切和轻微倾斜；同时记录节奏是否可见。标注者和复核者分别记录。

每张图一份 JSON 标注，manifest.jsonl 格式如下（占位值需替换）：

```json
{"sampleId":"real-001","image":"images/001.png","annotation":"annotations/001.json","sha256":"图像字节SHA256","kind":"real","split":"dev","group":"来源家族/曲目ID","source":"来源与版本","rights":"自有或授权说明","reviewStatus":"reviewed","annotator":"A","reviewer":"B"}
```

20 张 dev / 30 张 test。相同曲目、重渲染版本和同源片段归一组；先分组再划分。真正独立的新来源应留作后续外部分布测试。用以下命令检查来源字段、哈希、复核状态和分组泄漏：

```sh
uv run --locked python -m m0.check_manifest data/private/manifest.jsonl
```

哈希仅能查完全重复；近重复、歌曲别名和分组合理性还需人工审计。工具不会自动收集、上传或公开任何截图。

## 当前评分边界

`evaluate` 对小节边界和规范化事件序列计算 Levenshtein 编辑距离，事件包含弦/品位和已标注时序。和音排序、等值分数被规范化；模型不能靠更换 IDs 或省略预测取得高分。

报告样本数、有效数、精确匹配数、总编辑数/真值 token 数（可以大于 1）和逐样本错误。缺失或结构非法的预测按全删除计算，仍保留在分母；重复或额外 sampleId 直接拒绝。输入的真值必须合法。测封存集前必须由负责人明确选择测试文件，不默认扫描 private 目录。

该指标不是参考项目的 Core SER，不能横向比较。当前尚未实现 system 检测召回、音符级匹配、节奏独立评分、端到端页指标、置信度校准或校对耗时实验。不要将工具自检结果作为 M0 成功依据。

## 本地研究基线重跑

本次实例已在 `/workspace/shared/m0-baseline-venv` 安装独立 CPU 环境，固定代码和已校验权重分别位于 `/workspace/shared/m0-references/guitar-tab-omr` 与 `/workspace/shared/m0-model/best.pt`。这些文件不是本仓库的依赖或发布内容。现有文件可用时运行：

```sh
/workspace/shared/m0-baseline-venv/bin/python -m m0.run_baseline \
  --source /workspace/shared/m0-references/guitar-tab-omr \
  --checkpoint /workspace/shared/m0-model/best.pt \
  --image data/examples/baseline-smoke.png \
  --output reports/local/baseline-smoke.json
```

runner 会检查源码 HEAD 与权重 SHA256；首次在其他实例运行需获取同 revision 的代码和权重，并按 `reports/baseline-environment.txt` 安装 CPU 依赖。主项目 `uv sync` 不会安装数百 MB 的模型环境。当前只保留原始 Tabbox token 和运行元数据，不会将其误当规范 JSON 预测或真实集成绩。该 smoke 图没有时值记号，模型若生成时值只表示其先验输出，不能证明图中存在节奏信息。
